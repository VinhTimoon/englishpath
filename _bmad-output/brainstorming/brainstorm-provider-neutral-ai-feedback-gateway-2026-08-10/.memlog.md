- (technique by coach) Failure Analysis: use prior blocked stories and likely production failures as design inputs.
- (idea by coach) Make the gateway refuse any request that lacks an explicit feature, skill, prompt version, policy version, and idempotency key.
- (idea by coach) Represent provider-unavailable as a first-class safe outcome, never as an empty success response.
- (idea by coach) Use a local deterministic adapter that returns bounded advisory scaffolding, not fabricated learner feedback.
- (idea by coach) Record only allowlisted usage metadata: owner, feature, skill, versions, quota outcome, estimated cost band, correlation ID.
- (idea by coach) Hash learner input for idempotency evidence instead of persisting raw prompt or provider payload in audit records.
- (idea by coach) Separate quota reservation from provider execution so retries cannot double-consume budget.
- (idea by coach) Use a policy decision object with allowed, denied, unavailable, and invalid states that every adapter must honor.
- (idea by coach) Create an output firewall that strips score, rubric weight, hidden prompt, credential, and raw-provider fields before response or audit.
- (idea by coach) Make advisory feedback immutable and explicitly non-authoritative for progress and TOEIC score.
- (idea by coach) Treat missing licensed prompt provenance as a hard fail-closed condition, not a fallback to generic generated text.
- (idea by coach) Assumption Reversal: assume no provider will ever be available; design a useful gateway around transparent unavailable guidance and local validation.
- (idea by coach) Assumption Reversal: assume quota values change weekly; version every policy and never embed limits in controllers.
- (idea by coach) Assumption Reversal: assume audit storage is public; store only metadata safe to disclose and no raw content.
- (idea by coach) Assumption Reversal: assume retries arrive concurrently from multiple devices; make idempotency the primary state machine.
- (idea by coach) Assumption Reversal: assume every model output is malformed; validate structured output before any learner-visible mapping.
- (idea by coach) Assumption Reversal: assume learners are adversarial; derive identity, quota, and feature entitlements only from the authenticated principal.
- (idea by coach) Assumption Reversal: assume licensed content can be withdrawn; store source/version references and fail closed when withdrawn.
- (idea by coach) Assumption Reversal: assume cost estimation is uncertain; use bounded cost classes with explicit unknown/unavailable state instead of fake precision.
- (idea by coach) Assumption Reversal: assume policy owners disagree; require one canonical policy version and reject mixed-version requests.
- (idea by coach) Assumption Reversal: assume no durable audit database is approved; define a repository port and local no-op implementation without inventing schema.
- (idea by coach) Assumption Reversal: assume feedback must not be generated; make validation, rubric explanation, and learner next-step guidance useful without claiming AI output.
- (technique by coach) Solution Matrix: compare local adapter, no-op adapter, provider adapter, and deferred contract across safety, usefulness, cost, and reversibility.
- (idea by coach) Best matrix cell: local deterministic adapter plus provider-neutral port plus explicit unavailable outcome.
- (idea by coach) Best matrix cell: quota policy as pure function with injected clock and usage snapshot, tested without network.
- (idea by coach) Best matrix cell: repository port first, persistence adapter later, when owner has not approved Prisma fields.
- (idea by coach) Best matrix cell: safe projection before observability emission to prevent logs from becoming a leakage path.
- (idea by coach) Best matrix cell: idempotency ledger keyed by owner and client key, with request fingerprint conflict detection.
- (idea by coach) Best matrix cell: cost estimate represented as policy-defined bucket and model-neutral unit, never provider invoice claims.
- (idea by coach) Best matrix cell: contract tests shared by local and future providers, enforcing identical redaction and schema behavior.
- (idea by coach) Best matrix cell: feature-specific prompt registry with version and provenance metadata, no inline prompts in services.
- (idea by coach) Best matrix cell: abuse/rate-limit decision stays separate from learner progress and scoring state.
- (technique by coach) Utopia vs Dystopia Split-Screen: test the gateway against a perfect rollout and a catastrophic leakage/overcharge rollout.
- (idea by coach) Utopia: provider swaps require only an adapter registration because policy, redaction, and contract tests are stable.
- (idea by coach) Utopia: a learner can retry safely, see honest status, and never lose progress when feedback is unavailable.
- (idea by coach) Utopia: quota/cost evidence answers which feature used what policy without exposing content or credentials.
- (idea by coach) Utopia: local adapter powers staging smoke tests and browser journeys with deterministic fixtures.
- (idea by coach) Dystopia: a client submits a fake model name and bypasses quota; prevent by allowlisting all gateway fields.
- (idea by coach) Dystopia: a provider payload leaks into logs; prevent with allowlisted audit DTOs and redaction before logging.
- (idea by coach) Dystopia: repeated mobile retries charge quota twice; prevent with atomic reservation/idempotency state.
- (idea by coach) Dystopia: feedback accidentally becomes official score; prevent with type-level advisory-only outputs and no progress mutation port.
- (idea by coach) Dystopia: an expired Drive licence remains selectable; prevent with source publication/withdrawal checks.
- (idea by coach) Dystopia: cost drift silently breaks free beta; prevent with policy versioning, bounded cost buckets, and an explicit kill switch.
- (idea by coach) Dystopia: a local fixture is mistaken for production quality; mark adapter provenance and environment in every result.
- (insight by coach) Synthesis: the strongest design is local deterministic adapter + provider-neutral port + policy-versioned quota decision + idempotency ledger + safe projection before observability.
- (decision by coach) Chosen direction: implement only the contract boundary and local/no-op path once owner approves quota/cost/schema/prompt provenance; never activate paid provider or invent values.
- (insight by coach) Non-obvious connection: unavailable-state UX, fail-closed licensing, and cost uncertainty are one invariant—unknown external state must be explicit and must not become success, zero, or fabricated precision.
- (decision by coach) Required future tests form a provider swap safety net: contract tests must run unchanged against local and future provider adapters, including redaction, quota, retries, ownership, and advisory-only semantics.
