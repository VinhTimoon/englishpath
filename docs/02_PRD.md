# EnglishPath Product Requirements Baseline

## Scope And Traceability

This PRD projects `notes/englishpath_product_spec_v2.md` into concise, testable
requirements. Functional requirements use `FR-###`, non-functional requirements use
`NFR-###`, and critical flows use `UF-###` from `docs/03_USER_FLOWS.md`. Epic/story
mapping is intentionally refreshed in `EP0-ST015` immediately after this core
rebaseline.

## Functional Requirements

| ID     | Requirement                                                                                                                                                                   | Phase  | Flow refs                    | Testable outcome                                                                    |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | ---------------------------- | ----------------------------------------------------------------------------------- |
| FR-001 | Guests must be able to discover product tracks, consume public content, and complete a limited learning trial before registration.                                            | 1      | `UF-001`                     | A guest reaches useful content and a trial without an authenticated session.        |
| FR-002 | Learners must be able to register, sign in/out, recover access, and retrieve an application profile through backend-verified authentication.                                  | 0-1    | `UF-002`                     | A learner establishes or safely recovers an authenticated session.                  |
| FR-003 | Onboarding and basic placement must capture goal/track, current level, deadline, time budget, preferences, and an initial assessment result.                                  | 1      | `UF-003`                     | Persisted inputs produce a traceable starting level and track.                      |
| FR-004 | The roadmap engine must generate and recalculate 30/60/90/120-day plans using onboarding, placement, progress, and the selected learning track.                               | 1, 4-5 | `UF-003`, `UF-004`, `UF-009` | A learner receives a bounded plan with visible daily tasks.                         |
| FR-005 | The dashboard must answer "What should I learn today?" using due roadmap tasks, progress, streak, errors, and next actions.                                                   | 1      | `UF-004`                     | A learner can open one daily entry point and see current work.                      |
| FR-006 | A shared vocabulary taxonomy must represent level, topic, subtopic, collocation, related skills, track, and relevant TOEIC Part links.                                        | 0-1    | `UF-004`                     | Vocabulary can be navigated as a reusable mindmap rather than isolated lists.       |
| FR-007 | Vocabulary learning must support SRS scheduling, mastery state, pronunciation/examples, and learner-specific due review.                                                      | 1      | `UF-004`, `UF-005`           | Completed vocabulary updates the next review state.                                 |
| FR-008 | Daily practice must combine bounded vocabulary, quiz-card, sentence, and roadmap tasks and persist each outcome.                                                              | 1      | `UF-004`                     | A learner completes a useful daily session and sees persisted progress.             |
| FR-009 | Reviewable mistakes from quizzes, vocabulary, listening, and TOEIC must enter learner-specific Error Notebook workflows.                                                      | 1-5    | `UF-005`, `UF-006`, `UF-009` | Incorrect work is classified and scheduled for remediation.                         |
| FR-010 | Basic CMS capabilities must manage shared taxonomy/content, lifecycle state, source/license metadata, and human review.                                                       | 1      | `UF-007`                     | Editors can move valid content from draft to approved publication.                  |
| FR-011 | Progress must aggregate completion, accuracy, XP/streak, skill/track outcomes, and roadmap status without allowing client-authored scores.                                    | 1-6    | `UF-004`, `UF-006`           | Server-approved outcomes produce learner-visible progress.                          |
| FR-012 | TOEIC Listening & Reading question-bank workflows must support Parts 1-7, topic, difficulty, media/passage, explanation, source/license, and review status.                   | 2      | `UF-007`, `UF-008`           | Approved questions can be selected without exposing answer keys.                    |
| FR-013 | Learners must practice TOEIC Listening & Reading by Part, topic, difficulty, and selected remediation needs.                                                                  | 2      | `UF-008`                     | A learner completes targeted Part 1-7 practice.                                     |
| FR-014 | TOEIC must support mini tests, half tests, timed practice, server-owned scoring, and finalized results.                                                                       | 2      | `UF-008`                     | A timed session finalizes exactly once with protected answers.                      |
| FR-015 | TOEIC results must report score/accuracy, Part/skill weakness, time use, repeated errors, and vocabulary/grammar remediation.                                                 | 2      | `UF-006`, `UF-008`           | Finalized attempts produce actionable analysis and Error Notebook items.            |
| FR-016 | The licensed-content library must catalogue documents, video, audio, slides, spreadsheets/question banks, transcripts, images, folders, and links.                            | 3      | `UF-007`, `UF-010`           | Learners can search/filter approved assets by track, skill, topic, type, and level. |
| FR-017 | A Google Drive inventory/import workflow must extract metadata, validate rights, classify, segment, review, import, and publish without using Drive as the business database. | 0, 3   | `UF-007`                     | A changed source never publishes before checksum/version and review validation.     |
| FR-018 | Licensed listening must support controlled media, transcript, drills, shadowing, resume, and learner progress.                                                                | 3      | `UF-010`                     | A learner resumes and completes a licensed listening activity.                      |
| FR-019 | Library content must support bookmarks/notes and links to roadmap tasks, vocabulary, quizzes, and recommended next content.                                                   | 3      | `UF-004`, `UF-010`           | One canonical asset can participate in multiple learning tracks.                    |
| FR-020 | TOEIC Speaking must support approved task types, recording/submission, rubric evidence, and advisory feedback.                                                                | 4      | `UF-011`                     | A learner submits speaking work and receives rubric-aligned feedback.               |
| FR-021 | TOEIC Writing must support approved task types, text submission, rubric evidence, and advisory feedback.                                                                      | 4      | `UF-011`                     | A learner submits writing work and receives rubric-aligned feedback.                |
| FR-022 | TOEIC Four Skills must provide a balanced roadmap and dashboard that does not silently omit a selected skill beyond configured limits.                                        | 4      | `UF-003`, `UF-011`           | Four-skill progress and due practice are visible together.                          |
| FR-023 | Full mock tests and exam simulation must use server-owned timing, answer protection, finalization, and suspicious-event logging.                                              | 5      | `UF-012`                     | A full attempt is scored only after secure finalization.                            |
| FR-024 | Advanced Error Notebook and adaptive roadmap behavior must adjust recommendations from validated progress and recurring-error evidence.                                       | 5      | `UF-006`, `UF-009`           | Repeated weaknesses alter later review/roadmap recommendations.                     |
| FR-025 | AI explanation, speaking, and writing features must run through a backend gateway with quotas, prompt versions, structured outputs, and advisory-only results.                | 4-5    | `UF-011`, `UF-013`           | Every AI result has policy and usage evidence and cannot set an official score.     |
| FR-026 | Community sharing must support moderation, reporting, and safe publication controls.                                                                                          | 5      | `UF-013`                     | Reported content can be reviewed and moderated by an authorized role.               |
| FR-027 | Mobile clients must reuse backend APIs for auth, roadmap, practice, listening, speaking/writing, push, and approved offline content.                                          | 6      | `UF-002`, `UF-004`, `UF-010` | Mobile uses the same ownership and scoring rules as web.                            |
| FR-028 | Premium entitlements may expand quotas, offline access, and analytics without removing the useful free learning loop.                                                         | 6      | `UF-013`                     | Free users retain baseline value and premium checks are backend-owned.              |
| FR-029 | Admins must inspect operational health, content/license state, audit events, analytics, and AI usage through guarded capabilities.                                            | 0-6    | `UF-007`, `UF-013`           | Privileged operations are role-checked and auditable.                               |

## Non-Functional Requirements

| ID      | Requirement                                                                                                                                                             | Testable outcome                                                             |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| NFR-001 | Current implementation and planned target capabilities must be labeled separately.                                                                                      | Planning and review do not claim unbuilt modules are available.              |
| NFR-002 | Protected decisions, ownership, roles, scoring, roadmaps, rights, quotas, and answer validation remain backend-owned.                                                   | Client input cannot grant access or author authoritative outcomes.           |
| NFR-003 | REST endpoints use `/api/v1`, validated DTOs, documented errors, pagination for collections, and OpenAPI-visible contracts.                                             | Contract tests can assert stable request/response semantics.                 |
| NFR-004 | Controllers stay thin, services own business rules/transactions, and repositories own persistence access.                                                               | Architecture review finds no persistence or scoring logic in controllers.    |
| NFR-005 | Public and learner web surfaces define accessible loading, empty, error, success, and responsive states.                                                                | Critical journeys pass keyboard, screen-size, and accessibility checks.      |
| NFR-006 | Content retains source, checksum/version, usage scope, access tier, license, review, and publish metadata.                                                              | Published records are traceable to approved rights and review evidence.      |
| NFR-007 | Imported or AI-assisted content never auto-publishes and must pass human review.                                                                                        | Automated publication attempts fail closed.                                  |
| NFR-008 | TOEIC answer keys, authoritative timers, and official scoring remain server-side until validated finalization.                                                          | Pre-submit payloads contain no correct-answer material.                      |
| NFR-009 | AI providers are backend-only adapters with quota, cost, model/prompt version, schema validation, redaction, and abuse controls.                                        | AI calls are auditable and tests run with deterministic local adapters.      |
| NFR-010 | Storage, analytics, monitoring, email, queue, and AI boundaries support credential-free local/mock implementations.                                                     | CI and local tests require no paid-service credentials.                      |
| NFR-011 | Google Drive is an inventory source, not a public runtime database or automatic publication channel.                                                                    | Runtime business queries use application storage/data and reviewed versions. |
| NFR-012 | Search starts with PostgreSQL/full-text and pgvector-compatible design before specialist systems are approved.                                                          | No external search/vector/graph dependency is mandatory for early delivery.  |
| NFR-013 | Security includes backend JWT verification, RBAC/ownership, validation, rate limits, secret protection, signed/private media, redacted logs, and audit.                 | Unauthorized and malformed requests fail safely with evidence.               |
| NFR-014 | The platform retains an explicit path to roughly 300-500 concurrent users using indexes, caching, queues, and non-blocking heavy work where justified.                  | Load-sensitive stories document capacity assumptions and tests.              |
| NFR-015 | Automation may merge passed story branches only into `dev`; `dev` to `main`, production credentials, paid services, and destructive migrations remain owner-controlled. | Automation never promotes or activates protected production decisions.       |
| NFR-016 | Local development defaults remain frontend `4173` and backend `3005`.                                                                                                   | Approved local commands and examples resolve to those ports.                 |
| NFR-017 | Business-rule fixes for score, roadmap, rights, and exam sessions include happy, validation, boundary, and failure-path regression tests.                               | A rule cannot change only to satisfy an existing test.                       |
